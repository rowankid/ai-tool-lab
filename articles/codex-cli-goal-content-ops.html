Codex CLI / Agent Workflow

Codex CLI /goal 怎么用：把内容站迭代变成可复现任务（含验证与安全边界）

披露：本文不包含任何必须点击的商业链接；本站其他页面可能包含 affiliate 链接。本文目标是把“怎么让 Agent 稳定推进内容站迭代”讲清楚，并给你一份可复用的任务模板。

一句话结论

/goal 的价值不在于“更聪明的提示词”，而在于把模糊需求变成可验收、可回滚、可复现的任务： 让 Agent 知道要改哪些文件、什么算完成、以及怎么验证没把站点改坏。

先看 3 个事实：为什么 /goal 值得写得更具体

  • Codex 的任务本来就是“隔离执行”的：OpenAI 在产品介绍里明确把 Codex 定义为可并行处理任务的工程 agent， 每个任务在独立环境里运行，可读写代码并执行测试、lint 和类型检查。
  • 它会给你可验证证据：官方说明强调，完成任务后会附带终端日志和测试输出引用；这意味着你不该只看“写完了没有”，而要把验证标准写进任务本身。
  • 命令与行为变化很快：截至 2026-05-15，OpenAI 的 Codex GitHub releases 页面仍在持续更新 0.131.0-alpha.* 预发布版本（2026-05-12、2026-05-14 均有新条目），所以旧教程很容易过时，release notes 应该成为你的事实源。

/goal 是什么（以及它不是什麽）

  • 它是一个“任务对齐器”：把你的目标、范围与验收条件固定下来，减少 Agent 自行扩写范围导致的偏航。（命令与语义以 release notes 为准）
  • 它不是“自动发布按钮”：注册/登录、验证码、KYC、收款、外部发帖、投放等高风险动作仍然必须人工确认。
  • 它也不是 SEO 黑魔法：内容能否被搜索与 AI 引用，核心仍是可抓取、可理解、可引用的高质量原创增量内容，而不是某个命令。

中文内容站最容易漏掉的 /goal 字段

对内容站来说，真正让任务可复现的，往往不是“多写两句提示词”，而是把下面 4 类约束写死。

  1. 入口同步：新增或重写文章后，是否必须同步首页、主题 Hub、sitemap.xml、必要时同步 llms.txt。
  2. 事实门槛：至少 3 个事实核查点，优先官方来源；如果只是 X 上的讨论热词，必须退回到官方 release notes 或文档核验。
  3. 商业边界：是否允许加入 affiliate 链接；如果允许，要不要加披露和 rel="sponsored"；如果未获批，只能放普通官方链接。
  4. 发布验证：是否要做 HTML 解析、站内链接检查、rsync 到临时目录、本地 HTTP + curl 校验标题存在。

谁适合用 /goal

下面 3 类任务，特别适合用 /goal 作为“第一步”。

  1. 内容资产迭代：补 FAQ、补来源、补“适合/不适合”、补内部链接，把一篇文章从“能读”升级成“能长期带来流量与转化”。
  2. 站点一致性维护：新增文章后同步首页/Hub/sitemap/llms.txt，避免漏入口、漏内链、漏披露。
  3. 低风险批量修复：统一标题格式、修复站内死链、修正 canonical、修复披露文案或 rel 属性。

不适合交给 Agent 自动做的事（必须人工确认）

  • 任何“最终提交”动作：支付、购买、提现、税务表格、银行卡、KYC、邮箱验证码/人机验证。
  • 任何外部发布：X/公众号/邮件群发/论坛发帖（包括自动点赞、关注、私信）。
  • 任何会泄露秘密的内容：账号信息、token、内部链接、未授权截图与后台数据。

如果你希望 Agent 推进这些事情，正确方式是：让它做材料准备与检查清单，并在关键节点停下来等你确认。

一个可直接复用的 /goal 模板（内容站迭代版）

你可以把下面结构复制到 /goal 里（把方括号内容替换为你的实际信息）。

  1. 目标：要解决的读者问题 + 期望产出（例如：新增 1 篇文章页，并接入首页与 sitemap）。
  2. 范围：允许修改的目录（例如：`ai-affiliate-site/`）与明确要改的文件清单。
  3. 禁区：禁止做的事情（例如：不外部发布、不伪造发布日期、不提交任何表单、不处理验证码）。
  4. 质量门槛：首段给结论；至少 3 个事实核查点；中文用户角度；适合/不适合；≥3 个内部链接；披露与外链 rel。
  5. 验证：HTML 解析、站内链接检查、sitemap/llms.txt 更新、rsync 到 `/tmp`、curl 校验关键标题。

内容站的“最小验证闭环”清单

  • 解析所有 HTML：确认每页都有 <title>、无明显结构错误。
  • 站内链接检查：不允许出现新增的相对路径死链。
  • sitemap/首页/Hub/llms.txt：确保新增页在至少 2 个入口出现（首页文章区 + 主题 Hub/学习路线）。
  • 本地可读性：用 curl 读取新页面并校验关键 <title> 是否匹配。

这套闭环比“让 Agent 一次写 20 篇”更能长期产出稳定资产：它直接约束了薄内容、死链和站点漂移的风险。
