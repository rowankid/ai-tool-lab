AGENTS.md / AI Agent Ops

AGENTS.md 怎么写，才能让 Agent 真懂边界？

披露：本文可能包含 affiliate 链接。本文重点是内容站的 Agent 操作边界和质量门槛。

一句话结论

AGENTS.md 不是写给人看的愿望清单，而是写给 Agent 的操作边界。它要告诉 Agent： 站点是什么、哪些文件能改、什么叫高质量内容、哪些动作必须停下来等用户确认。

如果你同时在用 Claude Code、Codex 这类能读文件、改文件、跑命令的 agent，AGENTS.md 还应该顺手定义权限默认值与验证闭环。 否则 Agent 很可能“会做很多事”，但做出来的不是你想要的那一套。

内容站 AGENTS.md 应该包含什么

站点定位

一句话说明站点主线，例如 AI 内容增长实验室，而不是泛 AI 工具列表。

文件边界

哪些文件是公开站点、哪些是知识库、哪些是 secrets，不能混写。

质量门槛

首段结论、事实来源、内链、适合/不适合人群、披露和验证命令。

禁止动作

不伪造日期、不刷量、不自动外发、不处理 KYC/税务/收款/验证码。

权限默认值

先说明哪些任务默认只读/先计划，哪些任务才允许改文件与跑验证命令。

先写 3 个官方事实：边界不是靠“常识”自己长出来的

  • Claude Code 的 permission modes 是风险边界，不是效率开关：plan、default、acceptEdits、bypassPermissions 适合的任务强度不同。
  • Codex / Claude Code 这类工具会持续演化：教程和工作流要写“核验日期”与官方来源，避免旧命令或旧行为误导读者。
  • Google 对内容质量的核心要求没有因为 AI 搜索而改变：AGENTS.md 里仍要把首段结论、事实核查、内链与适用边界写成硬门槛。

可以直接使用的结构

# 项目定位
本站是 AI 内容增长实验室，主线为 SEO/GEO、AI Agent 工作流、Newsletter 和合规避坑。

# 发布规则
- 只发布通过质量门槛的页面。
- 不伪造发布日期；公开页可写“持续更新中”。
- 未获批工具只放普通官方链接。
- affiliate 链接必须披露并使用 rel="sponsored"。

# 质量门槛
- 标题回答明确搜索意图。
- 首段给结论。
- 至少 3 个事实核查点。
- 至少 3 个内部链接。
- 有适合/不适合人群或风险边界。

# 权限模式
- 默认先用 plan / 只读方式盘点范围。
- 批量改动前先列文件清单和验证命令。
- 验证通过前不要自动发布到外部平台。

# 必须暂停的动作
验证码、登录、注册最终提交、外部发帖、投放、购买、提现、税务、银行卡、KYC。

权限模式怎么写进 AGENTS.md

plan

适合盘点文章、找死链、列文件清单和判断是补旧文还是新开页。小时级运营迭代优先从这里开始。

default

适合单页补来源、补 FAQ、补内链这类中低风险动作；仍应保留验证和人工复查。

acceptEdits

只适合你已经明确写入范围和验证命令的批量修正，例如统一 canonical、披露或 sitemap 入口。

bypassPermissions

不该成为公开站点发布链路的默认选择；没有明确回滚点时不要放开。

为什么这对 SEO/GEO 有帮助

Agent 最大的问题不是不会写，而是太容易把站点写散。AGENTS.md 把定位、内链、披露和质量门槛固定下来， 让每次批量写作都沿着同一套框架推进。长期看，这比一次性生成很多文章更重要。

一个更实用的任务模板

  • 目标：只补强 1-2 篇既有高价值页面，并同步首页、相关 Hub、`sitemap.xml`。
  • 范围：只允许改 `ai-affiliate-site/` 与项目看板文档；不碰 secrets、账号配置和未授权截图。
  • 质量：首段结论、3 个事实核查点、中文用户角度、适合/不适合、3 个以上内部链接。
  • 验证：HTML 解析、站内链接检查、`rsync` 到 `/tmp`、`curl` 标题核验。
  • 停止条件：登录、注册、验证码、KYC、收款、外部发布、删除型同步都必须停下等人确认。

常见错误

  • 只写“请写高质量文章”，但没有定义高质量。
  • 没有说明默认先 plan，结果一上来就让 Agent 同时改首页、文章、sitemap 和外部发布链路。
  • 没有说明哪些外部动作不能自动做。
  • 没有把 secrets、账号、验证码和公开内容分开。
  • 没有要求验证命令，导致发布后才发现死链。
  • 允许 Agent 为了 SEO 修改日期或夸大收益。
